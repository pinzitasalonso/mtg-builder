# Spellpool web + backend (mtg-builder)

Next.js 16 (App Router, Turbopack) + Prisma 7 on better-sqlite3. **Railway auto-deploys every push to `main` to https://www.spellpool.com in ~3–5 min — a push is a production deploy; verify first.** This app is also the backend for the iOS app (`kukukaka/spellpool`).

## Commands

- Typecheck: `npx tsc --noEmit` · Tests: `npx vitest run` · Dev: `npm run dev`. GitHub Actions runs the typecheck and the tests on every pull request and on `main` (`.github/workflows/ci.yml`). It doesn't gate the Railway deploy.
- Route tests live in `test/routes/`. They call a route's handler against a real, empty SQLite file: import `@/test/db` **first** (it points `DATABASE_URL` at the file's own copy, then gives `prisma`, `makeUser`, `signIn`, `jsonRequest`, `params`). `next/headers` is a cookie jar there, and `fetch` fails, so nothing reaches the network. The empty database is built once per schema by `test/global-setup.ts`.
- Start (`npm start`) is `scripts/start.mjs`: one process that runs `scripts/prestart.mjs`, then the server, and passes SIGTERM on to it and exits 0. (As `prestart && next start` under a shell, the stop Railway sends the old version on every deploy made npm exit 143, and Railway emailed a "deploy crashed" each time.) The prestart step: copies the SQLite file to `<its folder>/backups` (when the schema changed or there's none from today; the newest 3 are kept), then `prisma db push` **without** `--accept-data-loss`. A schema change that would drop data (a rename is a drop plus an add) stops the boot and says what it would drop. Add the new column, move the data, and drop the old one in a later deploy; or set `ALLOW_DATA_LOSS=1` for one deploy when the loss is intended.
- Styling changes: verify on a production build (`npm run build && npx next start -p 4310`) — Turbopack dev HMR can half-apply (server module updates while the client bundle stays stale).

## Architecture

- API routes under `app/api/*` serve both clients: auth (session cookie), decks/cards/roles, collection, AI chat (streaming), play codes, subscription.
- Tiers: `User.tier` is written by the RevenueCat webhook (`app/api/revenuecat/webhook`), `app/api/subscription/sync` (the iOS app, on sign-in) and the admin page's "Re-check Pro" (`app/api/analytics/accounts/[id]/pro`, for web-only accounts: grant the `pro` entitlement in RevenueCat to customer `<User.id>`, then re-check), all via `lib/revenuecat.ts` `isProOnRevenueCat` — **tri-state**: a null (indeterminate) result must never change a stored tier; the webhook returns 500 on null so RevenueCat retries. An account is also Pro while a web (Stripe) subscription grants access: `lib/tier.ts` (`resolveTier`) is used by all three writers above, the Stripe webhook sets the tier as the subscription changes (`refreshTier`), and `/api/auth/me` promotes a free account that has one (`promoteIfSubscribed`). A finished web checkout is also handed to RevenueCat (`postStripePurchase`, with `REVENUECAT_STRIPE_PUBLIC_KEY`). Clients read tier from `/api/auth/me`. Free limits in `lib/limits.ts`; upgrade copy points at Spellpool Pro on `/pricing`. What people read on the site (the legal pages included) leaves the iOS app out for now.
- The free plan and the way to Pro: a free account gets 2 coach questions, 2 deck scans and 2 practice matches against the smart opponent a day (`lib/limits.ts`; the limit messages and every "a day" line of copy follow the numbers). A route that refuses answers 429 with one of the three limit messages, and the screen that shows it puts a button to `/pricing` beside it (`isLimitMessage`, `LimitNotice` in `components/Upgrade.tsx`). The same file has the header's plan pill (`PlanPill`: home, and a deck on a wide screen) and the bar across a deck once today's questions or scans are gone (`LimitBar`). They read the account once per page through `lib/plan-client.ts` (`usePlan`; `refreshPlan` after anything metered). After checkout, `/welcome` asks `/api/subscription/sync` until the account is Pro and leads back to the deck the player came from.
- The landing page (signed out, `app/page.tsx` with `lib/landing.ts`) shows the features as a grid of pictures (`components/LandingVisual.tsx`, the `.lv-*` styles): one large tile and seven small ones. Each picture is a small version of the app's own screen with real cards, drawn once at a fixed design size and scaled with its tile (the tile is a CSS container; `--u` is one design pixel). The words are one sentence, because the picture does the rest. Cards are pinned by Scryfall id to the stored scans, never looked up by name. A change to a screen the grid shows means a look at its picture too. The composition rules came from the Stageshow guide (github.com/benjitaylor/skills).
- Theming: `lib/identity-theme.ts` — a deck page's ground is its identity field sinking into a darkened cut of itself (mono + ten guilds hand-tuned, charcoal B, 3+ colors blend the monos); empty identity → the indigo felt. `LIGHT_VARS` is, despite the name, the dark panel set. Floating panels ride the JS-computed `--panel` var.
- The AI assistant (web, signed in) is one conversation for the whole app: `components/assistant/AssistantProvider.tsx` in the root layout, threads in `AssistantThread`/`AssistantMessage`. `/api/assistant` starts a reply and returns; `lib/assistant-runner.ts` writes it on the server (in-process — a restart marks it interrupted) and clients follow `/api/assistant/<id>/stream`. The deck on screen is sent as `deckId` and gets the deck research (`lib/assistant-context.ts`). Its `tournament_meta` tool reads MTGTop8 (`lib/mtgtop8.ts`: there's no API, so it parses the pages, one request at a time, cached six hours) for competitive metagames and winning lists; `/api/chat` gets it too, on a player's own deck. The iOS app keeps the stateless `/api/chat`. All AI routes (chat, search, roles, scan, primer, assistant) need a signed-in user; there is no guest AI budget.
- Printings: a deck card follows its owner's collection — `lib/owned-printings.ts` switches it to the printing they own when the owner opens the deck (GET `/cards`), and every add path defaults to it. A printing picked by hand sets `PoolCard.printingPinned` and is left alone; picking the owned printing unpins it.
- Collection: `GET /api/collection` has three sizes. `?summary=1` is the counts and a few pictured cards (the home page). `?prices=0` is every card, unpriced (a deck page). Plain is every card with its price (the collection screen, the iOS app): prices come from an in-memory cache (a day's life, empty after a deploy), and when more than 150 are missing the answer doesn't wait: it says `pricing: true` and `warmUsdPrices` fetches the rest in the background. Imported rows are matched to Scryfall by one job per user (`lib/collection-indexer.ts`); merges and "add" imports change quantities by increment, never by a total read earlier.
- Wishlist: the cards a player wants and doesn't have (`WishlistCard`, `app/api/wishlist`, `lib/wishlist.ts` + `lib/wishlist-client.ts`). It's the collection screen's second tab (`components/WishlistPanel.tsx` inside `CollectionView`), with a button beside the home page's collection block. Each card comes back with the copies owned now and its price; adding one that's already there raises its quantity, never sums; "Got it" (`POST { got }`) moves it into the collection. A deck's card sheet adds a card you're short of.
- Assemble deck (a deck tool, `components/deck/AssembleSheet.tsx`, `app/api/decks/[id]/assemble`): ticking the physical cards off as the deck is built. The tick is `PoolCard.assembled`; for unticked cards it shows the copies owned and which of the owner's other decks hold the card (ringed where it's ticked there), and it can send the unowned ones to the wishlist. It takes the whole screen (`ModalShell`'s `fullScreen`). A box finds a card by name, and a "Filters" button unfolds the filters (folded away at first; one that is on shows beside the button, with a tap to take it off): four numbers (all, to find, to find and owned, to find and not owned), the card's colour (its cost's colours, or a land's identity; several can be on), and one for each of the owner's other decks that holds a missing card ("Tick all" pulls a deck box's cards at once). It has two views, remembered on the device: the list, and the cards' pictures, where a tap ticks one and a dot says where it is. On a wide screen a side column shows the hovered card large. "Replace the N I haven't found" (owner only, `components/deck/ReplaceMissing.tsx`, `app/api/decks/[id]/assemble/replace`, `lib/assemble-replace.ts`) swaps the unticked cards for cards of the collection that do the same job. The model picks them in one call (it costs an AI ask, given back if the call fails) from the collection cut down to what could go in: inside the commander's colours, not already in the deck, with a copy that isn't in another of the owner's decklists. The commander and basic lands are never swapped. The answer is checked (`cleanSwaps`) and shown for review; the swaps kept are checked again and made either in the deck (the list as it was is saved as a version first, and the ticks stay) or in a new deck that is a copy with the swaps made.
- Tokens (a deck tool, `components/deck/TokensModal.tsx`, `app/api/decks/[id]/tokens`, `lib/deck-tokens.ts`): what the decklist's cards make that isn't in the deck. Tokens, and after them emblems and markers (the monarch, a dungeon). It comes from Scryfall's `all_parts`: one lookup of the deck's cards by name (the newest printing lists the tokens; an old one may not), one of the tokens for their pictures, both kept in memory for a day. The same token from different sets is merged by what it is (name, type, size, colours, text). A card whose text makes a token Scryfall lists no card for is named, to check by hand; when Scryfall didn't answer for some cards the list says it may be short.
- Decks need an account: `POST /api/decks` and `/api/decks/<id>/duplicate` return 401 when signed out. The web sends the player to /login, and home carries on afterwards (`lib/after-sign-in.ts`). Ownerless public decks (`userId` null) made before this rule still exist, and anyone can view and edit them.
- Practice games against the AI (`docs/practice-vs-ai.md`), from the playtest's "vs AI": `lib/practice/` is the pure engine (two playtest sides, mana, the effect vocabulary, combat with keywords, the AI's blocking and fallback planner), `app/api/practice/*` loads the decks (a Spellpool deck, a recent MTGTop8 list, or EDHREC's average deck for any commander, by bracket: `lib/edhrec.ts`; the opponent picker is `components/deck/OpponentPicker.tsx` over `lib/practice/opponents.ts`, opened from the deck page's "vs AI") and plans the AI's turn with one model call (`MODEL` in the turn route) returning a JSON plan that the browser's engine plays out and checks. `PracticeGame` rows count the free daily games (`FREE_PRACTICE_PER_DAY`) and cap AI turns per game; any failure falls back to the built-in planner. The two ways to play, Solo or Match, are two large choices at the top of the page where a match is set up, above "Pick an opponent" (`PlayWays` in `playtest-parts.tsx`; one under the other on a phone held upright). The solo table has "Play a match" in its row of buttons. Both tables share one title (`TableTitle`). A match is against the smart opponent; the basic one (that planner for every turn, in the browser: free, unlimited, `PracticeGame.bot`) is what the picker offers once today's free matches are used, not a choice beside it. A turn with nothing to decide skips the model (`simpleTurn`). The game is kept in the browser at each steady point so a reload resumes it (`lib/practice/save.ts`); its result goes on the deck's record (`/result`), and a finished game can be reviewed by the model (`/review`, kept on the row). The engine handles the AI's mana (fetches crack themselves, rituals float as a `mana` effect) and lets its hard counterspells answer your spells on your turn (`aiResponds`). Your side gets helpers: casts tap their mana (`playerCast`), tutors and fetch lands open a filtered library search (`searchOnCast`/`searchAbility`), and you can make tokens and add counters. Some commanders' abilities are carried out from their text on both sides: paying 2 life for {B} (K'rrik), "whenever you cast a … spell" triggers (K'rrik, Vivi, prowess), Kefka's discard-and-draw and its {8} sacrifice-and-transform (you pick through the game's `choice`), drawing on life loss (`loseLife`), and ninjutsu after blocks with Yuriko's reveal-and-drain (`ninjutsuOptions`, `aiNinjutsu`, `hitTriggersOf`). Also Winota, Vivi's and Selvala's mana, Braids's end step, Silas Renn's graveyard cast, Witherbloom's affinity and Beledros, Inalla's copies, Light-Paws with attached Auras, the Thranduils (lords, landfall, mana, loot), The Ur-Dragon and Kratos: the card readers are in `lib/practice/abilities.ts`. The common triggers of any card (enters, attacks, upkeep, end step, landfall, a creature entering or dying, an opponent drawing or casting) are read by `lib/practice/triggers.ts`, which carries one out only when it can do all of what the text says; lords, Auras and "all creatures have" become each card's `boost` after every move (`refreshStatics`). An Aura is cast only with something to go on, read from its "Enchant …" line (`enchantsOf`: a creature, a land, yours only, a player): the AI puts one that hurts on your permanent and any other on its own (`aiAuraHost`), and with neither it can't cast it. Equipment: "Equipped creature gets" is read like an Aura's bonus; your Equipment's menu has "Equip {N}" in your main phase (`playerEquip`: you pick the creature, then it's paid; `canEquip`), the opponent equips by activating it for its equip cost (`aiEquipHost`; the built-in planner equips what's on nothing), and an Equipment stays in play, on nothing, when its creature leaves. Both tables draw an attached card tucked behind the one it's on (`AttachGroup` in `playtest-parts.tsx`); the solo playtest has "Attach to…" and "Take it off" for any Equipment or Aura (`attachCard`, `detachCard` in `lib/playtest.ts`). Combat has first-strike and regular damage steps (double strike hits in both), deathtouch, trample, lifelink and menace, and the AI's blocks weigh the same fight (`exchange` in `lib/practice/ai.ts`). Both tables have Scry next to Draw. The library panel opens in draw order (the first card is the next one drawn), with "A to Z" beside it (`LibraryOrderBar`, `orderLibrary`). The AI's casts are staged (pay, then resolve or counter), so the table pauses for your answer when you could cast an instant; on your turn the AI also uses instant removal on a big attacker or, at end of turn, your biggest threat (`aiRemovalAction`). A removal spell's conditions are read from its text (`removalOf`: a colour, "if it's blue", a type, a cost, a size, a keyword), and one it doesn't know is not used as removal; the same check refuses a plan that aims a spell where its text doesn't allow (`mistargeted`: a Pyroblast on a red creature). Fast mana follows each card's own rules (`manaOutput`, `manaSources`): a permanent is a source only for its own "cost: add" ability, so reminder text about Treasures doesn't count; Mana Vault and the Monoliths stay tapped, the moxes check their conditions (Mox Diamond's land and Chrome Mox's imprint are a `choice` of yours), Jeweled Lotus pays for a commander only. Sneak shares ninjutsu's step but is a cast. Planeswalkers carry loyalty counters (`addLoyalty`), the end of your turn asks you to discard down to seven (`playerCleanup`), and a commander that dies or is exiled goes to its command zone (`moveTo`). Wheels (Wheel of Fortune and friends) are carried out for both players (`wheel`), and every draw passes Narset, Notion Thief and Hullbreacher (`drawCards`); Treasure makers are read in `lib/practice/treasure.ts` and every Treasure goes through `makeArtifacts` (Xorn, Academy Manufactor). The built-in planner also casts tutors, board wipes and draw spells it can carry out whole (`lib/practice/spells.ts`). Damage multipliers (Torbran, Fiery Emancipation, Furnace of Rath…) apply to every hit through `scaleDamage` (`lib/practice/damage.ts`); Thassa's Oracle, Laboratory Maniac and the library emptiers win (`lib/practice/wincons.ts`), the planner looks for those wins and for a lethal storm or burn turn first, and the AI counters a spell that wins or makes your attack lethal (`threatens`). The turn route plays a win the planner has checked before asking the model (`winningTurn`); storm spells are copied (`hasStorm`) and extra turns are taken (`PracticeGame.extraTurns`). The opponent knows its deck's combos: when a match starts, Commander Spellbook is asked for them (`deckCombos` in `lib/practice/combos.ts`, kept in the game's `setup`), with where each piece has to be. The engine can't play a loop out, so a combo is declared: a plan action of kind `combo` naming the combo's id. The table checks the pieces, their zones and the mana (`comboStatus`), announces it, always stops for your answer, checks the pieces again and carries out what it makes (`applyCombo`): a win, your library milled, or endless mana for the turn; anything else is only said in the log. The model is told the combos and where each stands every turn (`comboBrief`); the built-in planner casts the pieces it holds, goes for a ready combo, and its tutors fetch the missing piece. Of what Spellbook lists as other prerequisites, the table counts cards in the graveyard, or in the hand and graveyard (`comboNeeds`); the rest is not checked. The planner plays towards its combo (`goOff`, `comboLine` in `lib/practice/ai.ts`): it keeps the pieces that are worth nothing alone (`heldForCombo`) and its rituals, and the turn it can finish it makes the mana (free rocks, rituals, a creature sacrificed), tutors for the missing piece, casts the pieces and declares the combo. The line is tried on a copy of the table with the real moves, and nothing is cast unless it gets there; the old win lines are checked the same way before they're played. The turn route's `winningTurn` uses it, so a smart opponent's finishable combo is played by the table. After the plan's main actions the table looks again (`runAi` in `PracticeTable.tsx`): the built-in planner plans with the new hand, and a smart opponent takes a win the table can check. A turbo deck's tools are the table's to carry out: a ritual's mana (`ritualMana`: Dark Ritual, Cabal Ritual, Rite of Flame, Culling the Weak, Jeska's Will), "As an additional cost, sacrifice a creature" (`sacrificeCostOf`: the cheapest creature, a commander that costs {0} first), Phyrexian Tower's sacrifice when it's activated (`sacManaOf`), a Spirit Guide in the opponent's hand as mana (`handManaOf`), Gamble's random discard, and Ad Nauseam (down to 8 life). "At the beginning of the end step, sacrifice this" is carried out for both players (Underworld Breach, `endSacrifice` in `triggers.ts`), and Final Fortune's extra turn ends with its caster losing (`doomTurns`). To see what the planner does with a list, replay games of it turn by turn in a throwaway test (`newGame`, `fallbackPlan`, `applyAction`, `endTurn`) and read the logs. The table is `components/deck/PracticeTable.tsx`; both tables share `components/deck/playtest-parts.tsx`. On a phone both tables are played sideways: a `.pt-table` landscape block in `globals.css`, and a "turn your phone sideways" screen when it's held upright (an iPhone can't be rotated by a page; Android gets fullscreen plus an orientation lock).
- Web billing with Stripe, using Managed Payments: purchases are sold through Link, Stripe's merchant of record, which handles VAT and sales tax. (Paddle turned the account down; its tables `PaddleCustomer`/`PaddleSubscription` stay in the schema for one deploy and are to be dropped in a later one.) `/pricing` shows Pro's prices, found by lookup key (`spellpool_pro_monthly`/`_yearly` in `lib/pricing-tiers.ts`; `scripts/stripe-setup.mjs` creates the product, with tax code `txcd_10103000`, and the prices, tax included, in a sandbox or the live account). Managed Payments refuses `automatic_tax`, `tax_id_collection` and `payment_method_types`. The server needs `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`; the browser needs no Stripe key (`lib/stripe.ts`, with the SDK's fetch client). `User.tier` still comes from RevenueCat. `app/api/stripe/webhook` verifies the signature on the raw body and mirrors customers and subscriptions into `StripeCustomer`/`StripeSubscription` (`lib/stripe-webhook.ts`: upserts keyed on Stripe ids, skipped when the event is older than the one that wrote the row; links fill an empty `userId` from server-written metadata, never move one). `/account` shows the plan and opens Stripe's customer portal for the session's own customer (`portalUrl`). The Terms, Privacy and `/refund` pages name Link (Stripe) as the seller, linked from the home footer. Paywall copy follows the naming rule below (Paddle classed the app as an AI chatbot): the deck coach, practice matches, Deck Score scans.
- Spellpool Dial (`docs/dial-device-api.md`): a round screen with a knob that counts life by a deck. Its firmware is its own repository; this app is its backend. A dial pairs like a TV: it shows a code (`/api/device/pair/start`), its owner types it at `/dial` (`claim`), and the dial collects a token (`poll`) whose hash is kept on `Device`. Paired, it reads the decks sent to it (`/api/device/decks`) and their commander art as a 360 × 360 baseline JPEG (`/api/device/art/<deck>`, `lib/device-art.ts`). `lib/device.ts` is the logic; `scripts/dial-sim.mjs` plays a dial with no hardware.
- Play codes are single-use with per-IP throttles; security headers are set app-wide.
- What clients may store: routes read bodies with `jsonBody` and cards with `cleanCardInput` (`lib/api.ts`). Card and deck text is cut to a card's size, and a card image must be Scryfall's (or Gatherer's): stored images are shown to everyone who can see the deck.
- Sign-in limits (`lib/ratelimit.ts`): per IP for every auth action; wrong passwords also count per address and IP (5 in 15 minutes) and per address (30 an hour), charged on failure only, so signing in right never locks an address. A web Google sign-in is tied to the browser that started it by a cookie named after the state (`oauthStateCookie`). `clientIp` is the first `x-forwarded-for` entry: Railway's edge writes that header itself as "client, its own hop", so the last entry is the same for every visitor and must never be the key. The admin page's last line shows the forwarding headers the server sees.
- The Stats pane of a deck (`components/deck/DeckStatsPane.tsx`, its pieces in `DeckInsight.tsx`, the `.st-*` styles) leads with the Score: the number, the bracket, the four axes with their working a click away, and the scan's verdict (what the deck is, what beats it, its note on each axis). Under it, two columns on a wide page: combos, the game plan and the record; and the build (figures, curve, composition, colours, roles). The game plan is one thing to read: the primer, or the scan's piloting half (plan, opening hands, key cards, tips) behind a switch, never both stacked. Combos are always shown, each with its pieces as cards. Every card name on the pane shows the card when pointed at (`components/deck/CardHover.tsx`: `CardName`, `LinkedText` for names found in plain text, `CardThumb`). The deck page's top line shows the last Score too (`scan` on `GET /api/decks/<id>`).
- Deck Score: `lib/deck-score.ts` is the rubric maths (DeckCheck's published CRISPI ladders), `lib/deck-score-classify.ts` reads a decklist into its counts (curated staples in `lib/deck-score-cards.ts`, oracle text for the rest), `lib/goldfish.ts` simulates hands for the Speed axis, `lib/deck-score-report.ts` assembles the payload, and `lib/deck-analysis.ts` is the AI's written analysis plus its two judgement calls, which are shown in the working but never move the number: the Score is measured only, so the same list always scores the same (the goldfish deals every deck from one seed). `app/api/decks/[id]/scan` runs both on demand (metered: `FREE_SCANS_PER_DAY` free scans a day, unlimited on Pro) and stores the result on `Deck.analysis` for both clients. `/api/decks` sends a deck's last scan as `scan` (Score and bracket, from `scanSummary`), not the stored JSON; the home tiles show it. A card scored wrongly is fixed by a line in the cards file, not by a special case in the classifier. `npm run calibrate` scores the reference decks in `calibration/decks/` (DeckCheck scans, plus rubric anchors) and diffs each axis — run it after any scoring change; it is not part of `npm test` because it hits Scryfall and Spellbook.

## Gotchas

- Tailwind v4 (lightningcss) **mangles `color-mix()`** in globals.css — compute mixes in JS and set CSS vars (that's why `--panel` exists).
- Railway env-var edits stage until Deploy is clicked.
- JSX collapses the space after an inline closing tag (`</b> text`) — use `{" "}`.
- **Scryfall rate limits:** every `api.scryfall.com` request goes through `scryfallFetch` (`lib/scryfall-limit.ts`). It keeps search, named, random and collection to 2 a second, and everything else to 10. A 429 stops all requests for 30 seconds, because ignoring one risks a ban. Card art comes from the stored scans on `cards.scryfall.io`, which has no limit (`scanVersionURL` in `lib/scan-url.ts`), not from API lookups by name. A guard test fails on a direct `fetch` of an API URL.
- RevenueCat v1 subscriber reads work with the **public `appl_` key**; V2 `sk_` keys fail those endpoints and must never be committed or handled.

## Conventions

- tsc + vitest green before committing. Commit + push verified work.
- **Keep chat replies short.** Say what changed and what's unverified. Skip the rationale unless Kike asks for it, or it's a decision he has to make. The commit message and the PR body are where the reasoning goes.
- **What people read never says "AI".** The assistant is "the deck coach" (or "the coach"); the daily AI ask is "a coach question"; AI search is "smart search"; the primer button is "Draft it for me"; vs AI is "a practice match" against a smart or a basic opponent. Code, comments and the admin page keep their names. The Privacy and Terms pages still say that Anthropic's language model writes the coach's answers: that disclosure stays.
- **Use plain language, short sentences, and avoid dense or overly compressed phrasing.** One idea per sentence. Don't stack clauses to save a line.
- No `Co-Authored-By: Claude …` trailer — not in commits, not in chat replies. GitHub adds one by itself to a squash merge when the branch's commits aren't the merger's. Pass the full commit message on the merge call (`commit_message`) and it doesn't.
- Deeper context for a Claude Project (chat): `docs/claude-project-instructions.md` in the iOS repo.
