# Spellpool web + backend (mtg-builder)

Next.js 16 (App Router, Turbopack) + Prisma 7 on better-sqlite3. **Railway auto-deploys every push to `main` to https://www.spellpool.com in ~3–5 min — a push is a production deploy; verify first.** This app is also the backend for the iOS app (`kukukaka/spellpool`).

## Commands

- Typecheck: `npx tsc --noEmit` · Tests: `npx vitest run` · Dev: `npm run dev`
- Start (`npm start`) runs `scripts/prestart.mjs` first: it copies the SQLite file to `<its folder>/backups` (when the schema changed or there's none from today; the newest 3 are kept), then `prisma db push` **without** `--accept-data-loss`. A schema change that would drop data (a rename is a drop plus an add) stops the boot and says what it would drop. Add the new column, move the data, and drop the old one in a later deploy; or set `ALLOW_DATA_LOSS=1` for one deploy when the loss is intended.
- Styling changes: verify on a production build (`npm run build && npx next start -p 4310`) — Turbopack dev HMR can half-apply (server module updates while the client bundle stays stale).

## Architecture

- API routes under `app/api/*` serve both clients: auth (session cookie), decks/cards/roles, collection, AI chat (streaming), play codes, subscription.
- Tiers: `User.tier` is written by the RevenueCat webhook (`app/api/revenuecat/webhook`), `app/api/subscription/sync` (the iOS app, on sign-in) and the admin page's "Re-check Pro" (`app/api/analytics/accounts/[id]/pro`, for web-only accounts: grant the `pro` entitlement in RevenueCat to customer `<User.id>`, then re-check), all via `lib/revenuecat.ts` `isProOnRevenueCat` — **tri-state**: a null (indeterminate) result must never change a stored tier; the webhook returns 500 on null so RevenueCat retries. Clients read tier from `/api/auth/me`. Free limits in `lib/limits.ts`; upgrade copy points at Spellpool Pro in the iOS app.
- Theming: `lib/identity-theme.ts` — a deck page's ground is its identity field sinking into a darkened cut of itself (mono + ten guilds hand-tuned, charcoal B, 3+ colors blend the monos); empty identity → the indigo felt. `LIGHT_VARS` is, despite the name, the dark panel set. Floating panels ride the JS-computed `--panel` var.
- The AI assistant (web, signed in) is one conversation for the whole app: `components/assistant/AssistantProvider.tsx` in the root layout, threads in `AssistantThread`/`AssistantMessage`. `/api/assistant` starts a reply and returns; `lib/assistant-runner.ts` writes it on the server (in-process — a restart marks it interrupted) and clients follow `/api/assistant/<id>/stream`. The deck on screen is sent as `deckId` and gets the deck research (`lib/assistant-context.ts`). Its `tournament_meta` tool reads MTGTop8 (`lib/mtgtop8.ts`: there's no API, so it parses the pages, one request at a time, cached six hours) for competitive metagames and winning lists; `/api/chat` gets it too, on a player's own deck. The iOS app keeps the stateless `/api/chat`. All AI routes (chat, search, roles, scan, primer, assistant) need a signed-in user; there is no guest AI budget.
- Printings: a deck card follows its owner's collection — `lib/owned-printings.ts` switches it to the printing they own when the owner opens the deck (GET `/cards`), and every add path defaults to it. A printing picked by hand sets `PoolCard.printingPinned` and is left alone; picking the owned printing unpins it.
- Wishlist: the cards a player wants and doesn't have (`WishlistCard`, `app/api/wishlist`, `lib/wishlist.ts` + `lib/wishlist-client.ts`). It's the collection screen's second tab (`components/WishlistPanel.tsx` inside `CollectionView`), with a button beside the home page's collection block. Each card comes back with the copies owned now and its price; adding one that's already there raises its quantity, never sums; "Got it" (`POST { got }`) moves it into the collection. A deck's card sheet adds a card you're short of.
- Assemble deck (a deck tool, `components/deck/AssembleSheet.tsx`, `app/api/decks/[id]/assemble`): ticking the physical cards off as the deck is built. The tick is `PoolCard.assembled`; for unticked cards it shows the copies owned and which of the owner's other decks hold the card (ringed where it's ticked there), and it can send the unowned ones to the wishlist.
- Decks need an account: `POST /api/decks` and `/api/decks/<id>/duplicate` return 401 when signed out. The web sends the player to /login, and home carries on afterwards (`lib/after-sign-in.ts`). Ownerless public decks (`userId` null) made before this rule still exist, and anyone can view and edit them.
- Practice games against the AI (`docs/practice-vs-ai.md`), from the playtest's "vs AI": `lib/practice/` is the pure engine (two playtest sides, mana, the effect vocabulary, combat with keywords, the AI's blocking and fallback planner), `app/api/practice/*` loads the decks (a Spellpool deck, a recent MTGTop8 list, or EDHREC's average deck for any commander, by bracket: `lib/edhrec.ts`) and plans the AI's turn with one model call (`MODEL` in the turn route) returning a JSON plan that the browser's engine plays out and checks. `PracticeGame` rows count the free daily games (`FREE_PRACTICE_PER_DAY`) and cap AI turns per game; any failure falls back to the built-in planner. The engine handles the AI's mana (fetches crack themselves, rituals float as a `mana` effect) and lets its hard counterspells answer your spells on your turn (`aiResponds`). Your side gets helpers: casts tap their mana (`playerCast`), tutors and fetch lands open a filtered library search (`searchOnCast`/`searchAbility`), and you can make tokens and add counters. Some commanders' abilities are carried out from their text on both sides: paying 2 life for {B} (K'rrik), "whenever you cast a … spell" triggers (K'rrik, Vivi, prowess), Kefka's discard-and-draw and its {8} sacrifice-and-transform (you pick through the game's `choice`), drawing on life loss (`loseLife`), and ninjutsu after blocks with Yuriko's reveal-and-drain (`ninjutsuOptions`, `aiNinjutsu`, `hitTriggersOf`). Also Winota, Vivi's and Selvala's mana, Braids's end step, Silas Renn's graveyard cast, Witherbloom's affinity and Beledros, Inalla's copies, Light-Paws with attached Auras, the Thranduils (lords, landfall, mana, loot), The Ur-Dragon and Kratos: the card readers are in `lib/practice/abilities.ts`; lords, Auras and "all creatures have" become each card's `boost` after every move (`refreshStatics`). Combat has first-strike and regular damage steps (double strike hits in both), deathtouch, trample, lifelink and menace, and the AI's blocks weigh the same fight (`exchange` in `lib/practice/ai.ts`). Both tables have Scry next to Draw. The AI's casts are staged (pay, then resolve or counter), so the table pauses for your answer when you could cast an instant; on your turn the AI also uses instant removal on a big attacker or, at end of turn, your biggest threat (`aiRemovalAction`). The table is `components/deck/PracticeTable.tsx`; both tables share `components/deck/playtest-parts.tsx`. On a phone both tables are played sideways: a `.pt-table` landscape block in `globals.css`, and a "turn your phone sideways" screen when it's held upright (an iPhone can't be rotated by a page; Android gets fullscreen plus an orientation lock).
- Play codes are single-use with per-IP throttles; security headers are set app-wide.
- Deck Score: `lib/deck-score.ts` is the rubric maths (DeckCheck's published CRISPI ladders), `lib/deck-score-classify.ts` reads a decklist into its counts (curated staples in `lib/deck-score-cards.ts`, oracle text for the rest), `lib/goldfish.ts` simulates hands for the Speed axis, `lib/deck-score-report.ts` assembles the payload, and `lib/deck-analysis.ts` is the AI's written analysis plus its two judgement calls, which are shown in the working but never move the number: the Score is measured only, so the same list always scores the same (the goldfish deals every deck from one seed). `app/api/decks/[id]/scan` runs both on demand (metered: one free scan a day, unlimited on Pro) and stores the result on `Deck.analysis` for both clients. `/api/decks` sends a deck's last scan as `scan` (Score and bracket, from `scanSummary`), not the stored JSON; the home tiles show it. A card scored wrongly is fixed by a line in the cards file, not by a special case in the classifier. `npm run calibrate` scores the reference decks in `calibration/decks/` (DeckCheck scans, plus rubric anchors) and diffs each axis — run it after any scoring change; it is not part of `npm test` because it hits Scryfall and Spellbook.

## Gotchas

- Tailwind v4 (lightningcss) **mangles `color-mix()`** in globals.css — compute mixes in JS and set CSS vars (that's why `--panel` exists).
- Railway env-var edits stage until Deploy is clicked.
- JSX collapses the space after an inline closing tag (`</b> text`) — use `{" "}`.
- **Scryfall rate limits:** every `api.scryfall.com` request goes through `scryfallFetch` (`lib/scryfall-limit.ts`). It keeps search, named, random and collection to 2 a second, and everything else to 10. A 429 stops all requests for 30 seconds, because ignoring one risks a ban. Card art comes from the stored scans on `cards.scryfall.io`, which has no limit (`scanVersionURL` in `lib/scan-url.ts`), not from API lookups by name. A guard test fails on a direct `fetch` of an API URL.
- RevenueCat v1 subscriber reads work with the **public `appl_` key**; V2 `sk_` keys fail those endpoints and must never be committed or handled.
